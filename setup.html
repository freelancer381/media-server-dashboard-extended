Welcome

Enter the setup token. The install script printed it at the end; it is also in setup-token.txt in the data folder (LXC: /var/lib/media-server-dashboard/) and in the log (journalctl -u media-server-dashboard, Docker: docker compose logs).

Account

You sign in to the dashboard with this user.

At least 10 characters. A new password signs out every browser.

Address

How should the dashboard be reached?

Used for links only (e.g. the webhook addresses). In your proxy: scheme http, forward to the container's IP, port 80, and add proxy_buffering off; for the live feed. This server serves plain HTTP and never redirects, so the proxy's HTTPS can't loop.

Note: this server runs without the bundled reverse proxy (Caddy). The domain is only stored; set up HTTPS in front of it yourself.

Proxmox

Provides CPU, memory, network, storage and the state of your containers and VMs. An API token with the PVEAuditor role (read-only) is enough.

Storages to show

None ticked = every active storage.

Watch these containers/VMs

Apps

Tick what you run. The URL is the app's address as this server sees it, including its URL base if it has one (e.g. http://192.168.1.21:7878). Each app shows its API key under Settings → General.

Custom apps

More *arr apps (Lidarr, Readarr, Whisparr …) or any tool with an HTTP address. They show up as a service on the dashboard and as staff in the office.

Start page

Your own overview with links to your services, beside the 3D office. Every tile shows whether the service is reachable; with a linked Proxmox guest also CPU, memory and traffic. The host's numbers are on top.

Live feed

What your apps do shows up in the office as a chat: grabbed, imported, subtitles found, someone is watching. The dashboard notices some of it itself; with webhooks everything arrives at once and in full.

The webhook address is created when you save. You'll find it here in the settings afterwards.
